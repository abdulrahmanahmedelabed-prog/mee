# دليل المطوّر: البناء، التخصيص باسمك، الترخيص، والتركيب عند الزبون

## 1. تخصيص البرنامج باسمك (مرة واحدة)
عدّل `core/vendor.py`:
```python
VENDOR_NAME = "شركة ... للبرمجيات"
VENDOR_PHONE = "970599123456"      # واتساب الدعم بالصيغة الدولية بدون +
VENDOR_WEBSITE = "facebook.com/..."
```
يظهر اسمك ورقمك في شريط التجربة، وفي «الترخيص والتفعيل»، وزر «طلب التفعيل عبر واتساب» يفتح محادثتك مباشرة ومعه رمز جهاز الزبون.

## 2. مفاتيح الترخيص (مرة واحدة)
```bash
python tools/license_tool.py init
```
- المفتاح **الخاص** يُحفظ في `~/.shop_license/private_key.json` (مجلدك الشخصي، خارج المشروع).
  - **انسخه على فلاشة وفي مكان آمن.** إن فقدته لن تستطيع إصدار مفاتيح لنسخك الموزعة.
  - **لا ترفعه على GitHub أبداً ولا ترسله لأحد.** من يملكه يستطيع إصدار مفاتيح مجانية.
- المفتاح **العام** يُكتب في `core/license_pubkey.py` — اعمل له commit؛ يُبنى مع البرنامج.

## 3. بناء نسخة ويندوز
على جهاز ويندوز مع Python 3.10+:
```bat
build_exe.bat
```
الناتج في `dist\ShopAccounting\`. انسخ **المجلد كاملاً** للزبون. لا تنسخ مجلد `tools` ولا مفتاحك الخاص.

> نصيحة احترافية: استخدم **Inno Setup** (مجاني) لصنع ملف تثبيت `Setup.exe` بأيقونة واختصار سطح مكتب، وفكّر لاحقاً بشهادة توقيع رقمي حتى لا يظهر تحذير ويندوز «ناشر غير معروف».

## 4. دورة حياة الترخيص

```
الزبون يثبّت البرنامج ← تجربة 30 يوماً كاملة الميزات (3 أجهزة)
        ↓
الإعدادات ← الترخيص والتفعيل ← «طلب التفعيل عبر واتساب» (يرسل لك اسم المحل ورمز الجهاز)
        ↓
أنت:  python tools/license_tool.py issue --machine XXXX-XXXX-XXXX-XXXX --shop "اسم المحل" --plan pro --terminals 3
        ↓
ترسل المفتاح (SA1....) بالواتساب ← الزبون يلصقه ← «تفعيل» ✓
```

| الحالة | أمر الإصدار |
|---|---|
| جهاز واحد دائم | `--plan basic --terminals 1` |
| 3 أجهزة دائم | `--plan pro --terminals 3` |
| غير محدود | `--plan enterprise --terminals 0` |
| اشتراك سنوي | `--plan subscription --terminals 1 --expires 2027-09-30` |
| إضافة أجهزة لزبون | أصدر مفتاحاً جديداً لنفس رمز الجهاز بعدد أكبر |
| الزبون غيّر جهازه الرئيسي | خذ الرمز الجديد وأصدر مفتاحاً جديداً (بعد التأكد) |

- كل مفتاح يُسجَّل في `~/.shop_license/licenses_log.csv` (سجل زبائنك وتواريخ التجديد).
- التحقق من مفتاح: `python tools/license_tool.py verify "SA1...."`.
- **الترخيص على الجهاز الرئيسي فقط.** الأجهزة الفرعية تتبع ترخيص الرئيسي، والرئيسي يرفض الأجهزة الزائدة عن العدد.
- عند انتهاء التجربة أو الاشتراك: **البيع فقط يتوقف**. التقارير والديون والنسخ الاحتياطي تعمل — لا نحتجز بيانات الزبون.
- إرجاع ساعة الجهاز للوراء لا يمدد التجربة (البرنامج يتذكر أحدث تاريخ شاهده).

### حدود الحماية (بصراحة)
البرنامج مكتوب بـ Python، ومن يملك خبرة برمجية يستطيع نظرياً تعديل الكود لتجاوز الترخيص. الحماية الحالية تمنع **النسخ العادي بين المحلات** (وهو 99% من الحالات) ولا يمكن تزوير مفتاح بدون مفتاحك الخاص. لحماية أقوى لاحقاً: تجميع الكود بـ **Nuitka** بدل PyInstaller، وتفعيل عبر الإنترنت اختياري.

## 5. قائمة التحقق عند التركيب في المحل
- [ ] ويندوز محدَّث، والتاريخ والوقت صحيحان.
- [ ] نسخ البرنامج إلى `C:\ShopAccounting` + اختصار سطح المكتب.
- [ ] تعريف الطابعة الحرارية في ويندوز + ورق 80/58 + معاينة فاتورة.
- [ ] ماسح الباركود يكتب في Notepad ويضغط Enter تلقائياً.
- [ ] درج النقود: «تجربة فتح الدرج».
- [ ] معالج الإعداد: الاسم، العملة، الدولة، الضريبة، واتساب المالك.
- [ ] كلمة مرور المدير الجديدة مع المالك (لا تحتفظ بها أنت).
- [ ] مستخدم لكل كاشير.
- [ ] استيراد الأصناف + الأزرار السريعة + رموز الميزان + الكراتين.
- [ ] الديون القديمة للعملاء والموردين.
- [ ] مجلد النسخ الاحتياطي الثاني داخل Google Drive/OneDrive (وتأكد أن برنامج المزامنة مسجّل دخوله).
- [ ] عدة أجهزة: الجهاز الرئيسي بعنوان IP ثابت من الراوتر، جدار الحماية «سماح»، اختبار الاتصال من كل كاشير.
- [ ] لوحة المالك على جواله (واختيارياً Tailscale).
- [ ] AnyDesk/RustDesk للدعم عن بُعد.
- [ ] بيع تجريبي ← مرتجع ← إغلاق وردية ← حذف البيانات التجريبية (أو ابدأ بقاعدة نظيفة).
- [ ] تسليم «بطاقة الكاشير» مطبوعة.

## 6. التحديثات
1. طوّر وجرّب: `python -m pytest tests` (يجب أن تنجح كل الاختبارات).
2. ارفع رقم `VERSION` في `core/vendor.py`.
3. ابنِ exe جديداً.
4. عند الزبون: خذ نسخة احتياطية، ثم استبدل ملفات البرنامج **بدون لمس مجلد `data`**. قاعدة البيانات تُرقّى تلقائياً عند أول تشغيل (من أي نسخة سابقة، بدون فقدان بيانات)، والترخيص يبقى.

## 7. هيكل الكود الجديد في 4.0
```
core/ledger.py       القيد المزدوج: دليل الحسابات، توليد القيود، ميزان المراجعة، قائمة الدخل، الميزانية
core/cheques.py      الشيكات الواردة والصادرة
core/promotions.py   العروض التلقائية
core/loyalty.py      نقاط الولاء
core/reorder.py      الطلبيات الذكية
core/license.py      الترخيص والتجربة (التحقق فقط)
core/owner_web.py    لوحة المالك على الجوال (/owner على خادم البرنامج)
core/vendor.py       بياناتك كمزوّد
tools/license_tool.py  أداتك لإصدار المفاتيح (لا تُسلَّم للزبائن)
ui/accounting_screen.py  ui/cheques_screen.py  ui/promotions_screen.py  ui/reorder_screen.py  ui/setup_wizard.py
tests/test_v4.py     اختبارات الميزات الجديدة
```

**قاعدة مهمة عند إضافة وظائف جديدة:** أي دالة عامة في وحدات `core` المسجلة في `core/remote.py` (قائمة `MODULES`) تصبح متاحة للأجهزة الفرعية تلقائياً. إن كانت حساسة أضفها إلى `REQUIRED_PERMISSION`، وإن كانت تأخذ اتصال قاعدة بيانات داخلياً ابدأ اسمها بـ `_`.
