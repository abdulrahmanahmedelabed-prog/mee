# دليل المطوّر: البناء، التخصيص باسمك، الترخيص، والتركيب عند الزبون

## 1. تخصيص البرنامج باسمك (مرة واحدة)
عدّل `core/vendor.py`:
```python
VENDOR_NAME = "شركة ... للبرمجيات"
VENDOR_PHONE = "970599123456"      # واتساب الدعم بالصيغة الدولية بدون +
VENDOR_WEBSITE = "facebook.com/..."
```
يظهر اسمك ورقمك في شريط التجربة، وفي «الترخيص والتفعيل»، وزر «طلب التفعيل عبر واتساب» يفتح محادثتك مباشرة ومعه رمز جهاز الزبون.

## 2. مفاتيح الترخيص (مرة واحدة)
```bash
python tools/license_tool.py init
```
- المفتاح **الخاص** يُحفظ في `~/.shop_license/private_key.json` (مجلدك الشخصي، خارج المشروع).
  - **انسخه على فلاشة وفي مكان آمن.** إن فقدته لن تستطيع إصدار مفاتيح لنسخك الموزعة.
  - **لا ترفعه على GitHub أبداً ولا ترسله لأحد.** من يملكه يستطيع إصدار مفاتيح مجانية.
- المفتاح **العام** يُكتب في `core/license_pubkey.py` — اعمل له commit؛ يُبنى مع البرنامج.

## 3. بناء نسخة ويندوز
على جهاز ويندوز مع Python 3.10+:
```bat
build_exe.bat
```
الناتج في `dist\ShopAccounting\`. انسخ **المجلد كاملاً** للزبون. لا تنسخ مجلد `tools` ولا مفتاحك الخاص.

> نصيحة احترافية: استخدم **Inno Setup** (مجاني) لصنع ملف تثبيت `Setup.exe` بأيقونة واختصار سطح مكتب، وفكّر لاحقاً بشهادة توقيع رقمي حتى لا يظهر تحذير ويندوز «ناشر غير معروف».

## 4. دورة حياة الترخيص

```
الزبون يثبّت البرنامج ← تجربة 30 يوماً كاملة الميزات (3 أجهزة)
        ↓
الإعدادات ← الترخيص والتفعيل ← «طلب التفعيل عبر واتساب» (يرسل لك اسم المحل ورمز الجهاز)
        ↓
أنت:  python tools/license_tool.py issue --machine XXXX-XXXX-XXXX-XXXX --shop "اسم المحل" --plan pro --terminals 3
        ↓
ترسل المفتاح (SA1....) بالواتساب ← الزبون يلصقه ← «تفعيل» ✓
```

| الحالة | أمر الإصدار |
|---|---|
| جهاز واحد دائم | `--plan basic --terminals 1` |
| 3 أجهزة دائم | `--plan pro --terminals 3` |
| غير محدود | `--plan enterprise --terminals 0` |
| اشتراك سنوي | `--plan subscription --terminals 1 --expires 2027-09-30` |
| إضافة أجهزة لزبون | أصدر مفتاحاً جديداً لنفس رمز الجهاز بعدد أكبر |
| الزبون غيّر جهازه الرئيسي | خذ الرمز الجديد وأصدر مفتاحاً جديداً (بعد التأكد) |

- كل مفتاح يُسجَّل في `~/.shop_license/licenses_log.csv` (سجل زبائنك وتواريخ التجديد).
- التحقق من مفتاح: `python tools/license_tool.py verify "SA1...."`.
- **الترخيص على الجهاز الرئيسي فقط.** الأجهزة الفرعية تتبع ترخيص الرئيسي، والرئيسي يرفض الأجهزة الزائدة عن العدد.
- عند انتهاء التجربة أو الاشتراك: **البيع فقط يتوقف**. التقارير والديون والنسخ الاحتياطي تعمل — لا نحتجز بيانات الزبون.
- إرجاع ساعة الجهاز للوراء لا يمدد التجربة (البرنامج يتذكر أحدث تاريخ شاهده).

### حدود الحماية (بصراحة)
البرنامج مكتوب بـ Python، ومن يملك خبرة برمجية يستطيع نظرياً تعديل الكود لتجاوز الترخيص. الحماية الحالية تمنع **النسخ العادي بين المحلات** (وهو 99% من الحالات) ولا يمكن تزوير مفتاح بدون مفتاحك الخاص. لحماية أقوى لاحقاً: تجميع الكود بـ **Nuitka** بدل PyInstaller، وتفعيل عبر الإنترنت اختياري.

## 5. قائمة التحقق عند التركيب في المحل
- [ ] ويندوز محدَّث، والتاريخ والوقت صحيحان.
- [ ] نسخ البرنامج إلى `C:\ShopAccounting` + اختصار سطح المكتب.
- [ ] تعريف الطابعة الحرارية في ويندوز + ورق 80/58 + معاينة فاتورة.
- [ ] ماسح الباركود يكتب في Notepad ويضغط Enter تلقائياً.
- [ ] درج النقود: «تجربة فتح الدرج».
- [ ] معالج الإعداد: الاسم، العملة، الدولة، الضريبة، واتساب المالك.
- [ ] كلمة مرور المدير الجديدة مع المالك (لا تحتفظ بها أنت).
- [ ] مستخدم لكل كاشير.
- [ ] استيراد الأصناف + الأزرار السريعة + رموز الميزان + الكراتين.
- [ ] الديون القديمة للعملاء والموردين.
- [ ] مجلد النسخ الاحتياطي الثاني داخل Google Drive/OneDrive (وتأكد أن برنامج المزامنة مسجّل دخوله).
- [ ] عدة أجهزة: الجهاز الرئيسي بعنوان IP ثابت من الراوتر، جدار الحماية «سماح»، اختبار الاتصال من كل كاشير.
- [ ] لوحة المالك على جواله (واختيارياً Tailscale).
- [ ] AnyDesk/RustDesk للدعم عن بُعد.
- [ ] بيع تجريبي ← مرتجع ← إغلاق وردية ← حذف البيانات التجريبية (أو ابدأ بقاعدة نظيفة).
- [ ] تسليم «بطاقة الكاشير» مطبوعة.

## 6. التحديثات
1. طوّر وجرّب: `python -m pytest tests` (يجب أن تنجح كل الاختبارات).
2. ارفع رقم `VERSION` في `core/vendor.py`.
3. ابنِ exe جديداً.
4. عند الزبون: خذ نسخة احتياطية، ثم استبدل ملفات البرنامج **بدون لمس مجلد `data`**. قاعدة البيانات تُرقّى تلقائياً عند أول تشغيل (من أي نسخة سابقة، بدون فقدان بيانات)، والترخيص يبقى.

**قاعدة مهمة عند إضافة وظائف جديدة:** أي دالة عامة في وحدات `core` المسجلة في `core/remote.py` (قائمة `MODULES`) تصبح متاحة للأجهزة الفرعية تلقائياً. إن كانت حساسة أضفها إلى `REQUIRED_PERMISSION`، وإن كانت تأخذ اتصال قاعدة بيانات داخلياً ابدأ اسمها بـ `_`.


## 8. الجديد في 6.0 للمطوّر

### مُثبّت ويندوز (Setup.exe)
1. `build_exe.bat` ← 2. ثبّت **Inno Setup** وافتح `installer/ShopAccounting.iss` ← Compile.
- الناتج `dist/installer/ShopAccounting-Setup-6.0.exe`: اختصارات، استثناء في جدار الحماية للشبكة الخاصة، ومجلد `data` لا يُحذف ولا يُستبدل عند التحديث.
- عدّل `AppPublisher` واسم البرنامج. للتخلص من تحذير SmartScreen وقّع الملف بشهادة توقيع برمجيات.

### التنبيه بالتحديثات
- ضع في `core/vendor.py`: `UPDATE_URL = "https://موقعك/latest.json"` وانشر ملفاً مثل:
  `{"version": "6.1", "url": "https://موقعك/download", "notes": "إصلاحات"}`
- عند التشغيل يظهر للزبون زر «⬆ نسخة جديدة» إن كانت نسخته أقدم. لا يُرسل أي بيانات.

### نشر المتجر الإلكتروني على الإنترنت (بأمان)
البرنامج يخدم الصفحات على شبكة المحل (المنفذ 8765). لا تفتح المنفذ في الراوتر مباشرة. استخدم نفقاً آمناً يعطي رابط https:
- **Cloudflare Tunnel** (مجاني): `cloudflared tunnel --url http://localhost:8765` ثم اربط نطاقاً، وانشر رابط `/shop` فقط للزبائن.
- **Tailscale Funnel**: `tailscale funnel 8765`.
- ميزة إضافية: مع https تعمل كاميرا الجوال لمسح الباركود في تطبيق الموظفين `/m`.
- صفحات الإدارة (`/owner` و`/m`) محمية بتسجيل الدخول؛ أما `/rpc` فمحمي برمز الربط وتسجيل الدخول. يُفضّل مع النفق حصر المسار العام على `/shop` من إعدادات النفق.

### مكتبة جديدة
`qrcode` (لرمز الفاتورة الإلكترونية) أُضيفت إلى `requirements.txt`. إن لم تكن مثبتة يعمل البرنامج بدون الرمز.

## 9. الجديد في 7.0 للمطوّر

### استعادة كلمة مرور المدير
الزبون يضغط «نسيت كلمة المرور؟» ويرسل لك رمز الجهاز، فتصدر له رمزاً:
```bash
python tools/license_tool.py reset --machine 4F1A-9C03-7B2E-D5A8
```
الرمز (يبدأ بـ SR1) صالح 3 أيام ولمرة واحدة ولهذا الجهاز فقط. تحقّق من هوية المتصل قبل إصداره.

### الربط مع أجهزة الدفع البنكية
- الأوضاع (الإعدادات ← الطباعة ودرج النقود): **يدوي** (افتراضي)، **محاكي** (للعرض؛ أي مبلغ ينتهي بـ ‎.13 يُرفض لتجربة الرفض)، **جسر**.
- **بروتوكول الجسر (ShopPOS Terminal Bridge v1)** — HTTP/JSON على جهاز الكاشير:
  - `POST /sale` ← `{"amount": 12.5, "currency": "ILS", "reference": "POS-..."}` ← `{"approved": true, "auth_code": "123456", "rrn": "...", "card": "****1234", "message": "..."}`
  - `GET /status` ← `{"ok": true, "terminal": "اسم الجهاز"}`
- **ربط بنك حقيقي:** اطلب من البنك/مزوّد الجهاز «مواصفات ربط ECR» (Electronic Cash Register) أو مكتبة SDK. عدّل الدالة `process_sale` فقط في `tools/terminal_bridge.py` (رسالة البيع عبر COM/USB أو TCP وانتظار الرد) وشغّله على جهاز الكاشير: `python tools/terminal_bridge.py`. البرنامج نفسه لا يحتاج أي تعديل، ويمكنك كتابة جسر لكل بنك وبيعه كإضافة.
- أمان: البرنامج لا يرى رقم البطاقة كاملاً ولا يخزنه؛ فقط آخر 4 أرقام ورقم التفويض.

### تطبيق أندرويد
- المشروع في `android/` (Kotlin): يعرض صفحات البرنامج (`/m` للموظفين، `/owner` للمالك، `/shop` للمتجر) ويضيف مسح الباركود بكاميرا الجوال عبر Google Code Scanner (بدون صلاحية كاميرا وبدون https).
- **الربط:** من الإعدادات ← نقاط الولاء ولوحة المالك يظهر رمز QR بعنوان المحل؛ يمسحه التطبيق عند أول فتح (أو يُكتب العنوان يدوياً).
- **البناء:** يُبنى تلقائياً على GitHub Actions مع كل تعديل في `android/` (تبويب Actions ← «Android app (APK)» ← Artifacts ← `ShopPOS-android-debug`). للبناء محلياً: Android Studio ← Open ← مجلد `android` ← Build APK.
- **التثبيت المباشر:** أرسل ملف APK للزبون؛ يسمح بـ «التثبيت من مصادر غير معروفة» مرة واحدة.
- **النشر على Google Play:**
  1. حساب Google Play Console (25$ مرة واحدة).
  2. مفتاح توقيع (احفظه جيداً؛ فقدانه يمنعك من تحديث التطبيق):
     `keytool -genkeypair -v -keystore shoppos.jks -keyalg RSA -keysize 2048 -validity 10000 -alias shoppos`
  3. ابنِ نسخة موقّعة: عيّن المتغيرات `ANDROID_KEYSTORE_FILE` و`ANDROID_KEYSTORE_PASSWORD` و`ANDROID_KEY_ALIAS` و`ANDROID_KEY_PASSWORD` ثم `gradle -p android bundleRelease` (ملف `.aab`).
  4. ارفعه في Play Console مع الوصف والصور وسياسة خصوصية (التطبيق لا يجمع بيانات؛ يتصل بجهاز المحل فقط).
  - غيّر `applicationId` في `android/app/build.gradle.kts` لاسم نطاقك قبل أول نشر (لا يمكن تغييره بعدها)، وارفع `versionCode` مع كل تحديث.
- **آيفون:** يحتاج جهاز ماك وXcode وحساب Apple Developer (99$/سنة). حتى ذلك الحين: صفحة `/m` تعمل على سفاري ويمكن «إضافتها للشاشة الرئيسية».
